# Stage C1-v2语料重建

更新时间：2026-08-11 15:27 CST

## 当前状态

Stage C1已在step25942通过训练器的安全中断路径暂停。完整checkpoint已验证包含模型、optimizer、sampler游标和RNG策略，原GPU0–2训练进程已退出。当前不占用训练GPU。

数据重建状态为`IN PROGRESS`，全部CPU计算只提交到SLURM q03。只有数据、采样器、恢复配置和机器检查全部通过后才会生成新的`READY`状态；READY也不会自动占用GPU，仍需明确启动指令。

## 为什么重建

旧Stage C1训练索引有764,070条train记录，但只有578,613个唯一坐标窗口；185,457条是同坐标的额外重复记录。旧流程没有执行正反向互补归一、全局100%序列去重或近重复聚类，而且候选和编码阶段受名义15B碱基配额影响。旧训练采样比例也不是新的目标比例。

## Stage C1-v2数据合同

1. 不再用15B或其他总token数字裁剪训练池；候选全集由冻结的生物学锚点规则定义，所有通过质量检查和去重的候选都保留。
2. 相同`assembly + contig + start + end + context`只保留一条，重叠区域标签合并后只指定一个主要采样通道。
3. 每条DNA序列与其反向互补序列取统一canonical表示。
4. canonical序列100%完全相同时只保留一个训练代表，同时保存原始出现次数和来源列表。
5. 近重复窗口用真实序列比对确认：identity≥95%，且双方aligned coverage均≥90%。近重复成员不直接全部删除；大簇按次线性权重降低训练贡献。
6. 完全相同或近重复连接簇不得跨train、validation和test；留出集角色优先，冲突训练窗口不能进入训练池。
7. 建立5种长度×7种区域共35个独立池。池大小不强制等比例，训练时按实际处理token控制比例。
8. 长度token比例固定为4K/8K/16K/32K/64K=`5%/15%/5%/5%/70%`。
9. 每种长度内部的区域token比例固定为coding/splice/promoter/UTR/TES/gene body/background=`32%/21%/14%/11%/8%/10%/4%`。
10. 每个池内一个覆盖轮次无放回；跨轮允许受控复用。checkpoint保存35池游标、覆盖轮次、累计欠额和实际暴露统计。

## 恢复边界

Stage C1-v2改变语料目录、目录哈希、采样比例和sampler状态，因此不能把旧step25942的sampler游标直接称为新语料的exact resume。恢复时只继承经过验证的模型权重，重置optimizer和v2 sampler，并使用短warmup建立新的数据谱系；旧阶段暴露历史继续保留并如实披露。

## READY条件

- 同坐标重复为0；
- canonical 100%完全相同序列重复为0；
- train/validation/test的完全相同和近重复连接簇交叉为0；
- 35个池全部具有完整全局batch容量；
- 累计长度与区域token比例通过确定性重放；
- sampler checkpoint恢复后下一批序列和累计欠额完全一致；
- 随机抽查序列与源FASTA坐标一致；
- 数据manifest、代码、配置和checkpoint来源哈希闭合；
- CPU预检通过且GPU启动门保持关闭。
